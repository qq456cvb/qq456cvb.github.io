Overview

Shape dough with tools, without demonstrations

Dough changes shape with every touch, and making a donut takes several tools in the right order. Learned methods need demonstrations, which are hard to collect for long tasks and do not carry over to new shapes. Make a Donut plans in two levels instead: GPT-4 splits the task into stages, picking one tool per stage and writing Python code for the stage's goal shape; a closed-loop planner then reaches each goal by stepping through the space of Earth Mover's Distance (EMD) and finding tool motions with differentiable physics. Nothing is trained for the task.

Top level

GPT-4 writes the plan, one tool per stage

One prompt, shared by all tasks, describes four tools: a rolling pin, a gripper, a knife and a pole. A task is a single extra line, such as “The dough is initially a round ball at (0, 0, 0) with radius 1. Make a simple donut.” For every stage, GPT-4 answers with a one-line explanation, the tool, numpy code that builds the stage's goal point cloud, and the location and volume of each piece. Only the code is run; the rest is there to make GPT-4 reason before it writes the shape. Each stage uses one tool on one piece of dough.

Two guidelines keep the shapes realistic

Volume preserving: the dough cannot grow or shrink, so GPT-4 must derive each new shape's dimensions from the old volume. Chain of reasoning: it writes the formulas out step by step before the code. Without them, the planned shapes drift far from the dough's volume:

Bottom level

Planning in EMD space

Within a stage, the planner does not jump to the goal. It moves the current point cloud a few small steps toward the goal along the gradient of the Earth Mover's Distance, which gives the next reachable point cloud. Because EMD matches points one to one, every particle gets its own target:

p′i = pi − α · ∂ emd({pi}, {p̄i}) / ∂pi20 small steps from the current particles {pi} toward the stage's goal {p̄i}; the tool's motions are then optimized through differentiable physics with the per-point loss Σ ‖p′i − pi‖₁ (DiffPhysics-P2P), executed, and the loop repeats.

Try it below: pick a task and watch the particles step from one GPT-4 subgoal to the next. Colours follow each particle, so you can see the one-to-one matching.

GPT-4's stages

    step 0distance to goal 0.00

    A top-view illustration in your browser: simple shapes for each stage, exact EMD matching between consecutive goals, and the constant-size steps of the equation above. In the real method, tools and differentiable physics decide how the dough actually moves.

    1. Next reachable target20 EMD steps from the current dough give a nearby, reachable target with a per-particle correspondence.
    2. Point-to-point lossThe tool's actions are optimized so each particle moves to its own target, which gives better gradients than a plain EMD loss.
    3. Where to put the toolAt the start of a stage the tool goes where the biggest deformation is about to happen.
    4. Reset when stuckIf the EMD to the goal stops dropping, the tool is placed again, which escapes local minima.

    Simulation

    Four GPT-4 plans per task, all executed

    For each long task we ask GPT-4 four times and run every plan. The clips show one run per plan, one clip per stage. The plans differ in their details, yet the same planner carries all of them out.

    Ablations

    Every piece is needed

    Without GPT-4's plan, the EMD planner has no reachable intermediate goals and fails every long task. Without the volume-preserving and chain-of-reasoning guidelines, the plans' shapes are off and success drops to at most 25%. For single tools, removing the point-to-point loss hurts the most; initial tool placement and tool resetting matter less but still help.

    Values as printed on the paper's ablation charts.

    Real robot

    From simulation to real dough

    On a UFACTORY xArm 6, four depth cameras around the dough are fused with TSDF fusion into particles, so each stage starts from the real dough's state. The planner moves from there to GPT-4's goal in simulation, and the actions are replayed on the robot.

    Beyond code

    When a shape is hard to write as code

    GPT-4 can only plan shapes it can describe with simple numpy code. For harder ones, it can describe each stage's shape in words instead, and a text-to-3D model turns the words into point clouds. To make a bowl, GPT-4 asks for a “flattened sphere” and then a “bowl”; Point-E generates both, and the same EMD-space planner executes them.

    • Imperfect subgoals are fine: GPT-4's shapes are not always exactly reachable; the closed loop still gets close.
    • Speed: about 3 actions per second on a GPU.

    Abstract
    
    
    
      Read the full abstract
      
    Deformable object manipulation stands as one of the most captivating yet formidable challenges in robotics. While previous techniques have predominantly relied on learning latent dynamics through demonstrations, typically represented as either particles or images, there exists a pertinent limitation: acquiring suitable demonstrations, especially for long-horizon tasks, can be elusive. Moreover, basing learning entirely on demonstrations can hamper the model's ability to generalize beyond the demonstrated tasks. In this work, we introduce a demonstration-free hierarchical planning approach capable of tackling intricate long-horizon deformable manipulation tasks without necessitating any training. We employ large language models (LLMs) to articulate a high-level, stage-by-stage plan corresponding to a specified task. For every individual stage, the LLM provides both the tool's name and the Python code to craft intermediate subgoal point clouds. With the tool and subgoal for a particular stage at our disposal, we present a granular closed-loop model predictive control strategy. This leverages Differentiable Physics with Point-to-Point correspondence (DiffPhysics-P2P) loss in the Earth Mover Distance (EMD) space, applied iteratively. Experimental findings affirm that our technique surpasses multiple benchmarks in dough manipulation, spanning both short and long horizons. Remarkably, our model demonstrates robust generalization capabilities to novel and previously unencountered complex tasks without any preliminary demonstrations. We further substantiate our approach with experimental trials on real-world robotic platforms.
